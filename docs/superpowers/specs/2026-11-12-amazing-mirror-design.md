# AmazingMirrorDecomp

Create MatyMeatBoy/AmazingMirrorDecomp from the original katam history and combine independently useful work discovered across public forks and ports. The user requested the SS2 progress style, an inventory of existing work, and the latest project's actual commit age before implementation; that research was reported first. Existing authorization is to proceed autonomously with Sol low workers and MatyMeatBoy as the author of our changes.

## Approach

Preserve the matching GBA program as the authoritative profile. Audit all discoverable forks and independent implementations, pin source revisions, and deduplicate contributions by commit and code range. Replacing the base with a native port would lose the matching target; merging unrelated host runtimes would not establish decompilation progress. Native ports remain separately attributed references and potential future targets.

Use the newest original katam source as the starting point. Import unique matching contributions only when they are compatible and can pass the appropriate verification; document unresolved candidates instead of claiming their progress. Preserve original authors and history. Our commits use MatyMeatBoy.

## Reporting

Produce dark SVG code and naming treemaps, badges, JSON and Markdown with byte-weighted measured spans. Count generated C separately from embedded assembly, NONMATCHING fallback, intentionally retained assembly, unknown attribution and raw data. Deduplicate aliases. Do not infer semantic correctness from an existing name or turn preserved assets into identified data.

Prefer a complete linked inventory when the exact compiler and owned ROM permit it. A ROM-free object inventory must explicitly state its narrower denominator and exclude missing archives and auxiliary binaries; it must never be described as a matching ROM or complete-game percentage. Fingerprint sources and build provenance and reject stale metadata.

Keep normal matching recipes, checksums, C, ASM, headers, data and assets unchanged during reporting setup. Reporting tools run separately and never publish ROMs, objects, maps or extracted assets. CI may compile metadata without obtaining a ROM. The six-output top-level comparison remains required before claiming a full match; NONMATCHING compilation remains separate.

## Completion evidence

Deliver the fork, repository and local reuse inventory, reusable progress command, generated reports, meaningful guard tests, original credits, and a reviewed PR. Report the exact measurement scope and any ROM or toolchain validation still unavailable.
