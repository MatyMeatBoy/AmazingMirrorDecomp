## Task callback: raw and clamped distance

`sub_0802E78C` retains a raw halfword distance and a separate clamped register value. The raw value supplies the signed-halfword test. A local `u32` view in `r1` supplies the subsequent unsigned comparison and allows the zero path to reproduce `movs r0, #0; adds r1, r0, #0`.

The empty asm takes an initialized read-write zero result and the previous distance as an input. Its template emits no instruction and preserves the initialized physical bits at runtime. The operands keep the two values live at the required point. There are no untied, undefined output values and no hand-written machine instructions.

Natural alternatives included signed and unsigned scalar widths, separate raw/clamped variables, conditional expressions, the existing `abs` macro, and the established two-component vector types. These alternatives did not reproduce the complete target. The surviving constraints were then minimized on the final source:

| Removal experiment | Observed result |
|---|---|
| Remove the `r1` binding | One fixed byte differs at function offset `0x11C`: the sign-test shift reads `r1` instead of `r0`. |
| Remove the initialized empty asm | The zero is assigned directly; the target's zero-copy instruction and subsequent branch/pool placement differ. |
| Remove the previous-distance input | The same zero-copy requirement is lost. |
| Remove an additional view barrier or `volatile` qualifier | Matching survives; both were removed. |

The position scaling also uses multiplication by `0x100`. `Rand16()` expands to a shift of the `u32` `gRngVal`, so the masked random value and the subtraction of eight are unsigned. The previous left shift and the multiplication both perform defined unsigned arithmetic modulo `2^32`; this change is an equivalent source spelling, not a repair of signed-shift undefined behavior.

## Shotzo frame callbacks: object and Y-offset lifetimes

Both Shotzo drafts initially had the correct complete body size and only three wrong fixed bytes. At function offset `0x62`, the natural store computed the `objBase55` address in `r2`; the target uses `r1`. Fixing the field pointer alone caused a wider object/table register swap.

The final source keeps a local signed-byte pointer to the actual `objBase55` member in `r1`. An empty entry asm clobber excludes `r2` from the object's live range at that point, preserving the target's object in `r3` and table pointer in `r2`. This is compiler register pressure, not a hardware register write or a synchronization barrier.

| Removal experiment | Observed result |
|---|---|
| Remove the entry clobber | The first fixed difference is at `+0x2`; the object/table swap changes 16 bytes in the first callback and 20 in the second. |
| Remove the field pointer's `r1` binding | Exactly three fixed bytes differ at `+0x62`, reproducing the original Y-address discrepancy. |
| Replace the high-byte frame projection with a plain `u8` frame | The initial shift pair disappears and the bodies become four bytes smaller. |
| Remove the field's extra empty asm, value input, or the entry asm's object operands | Matching survives; all of these unnecessary operands/barriers were removed. |

Typed offset pairs, signed table elements, subobject pointers, declaration scopes, scalar Y-offset temporaries and a shared inline frame helper were also checked before retaining the local constraints. The explicit cast to `u32` makes the frame projection unsigned over the full byte range and retains the verified instructions.

## Scope and remaining uncertainty

These checks establish exact emitted code under the pinned compiler. They do not establish that the register bindings, empty asm, source expressions or unknown field names reproduce the historical source. The local `TODO(match)` comments identify the remaining compiler-steering debt and its measured purpose.

The 872-byte `sub_0811AB74` aiming callback is outside these recoveries. Its readable draft and control-flow experiments receive no matching-C credit. No object files, ROM bytes or temporary experiment ledgers are stored in this document or committed with it.
